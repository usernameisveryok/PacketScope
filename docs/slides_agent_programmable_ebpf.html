The Problem: Static Rules Cannot Keep Pace

Limitations of Rule-Based Filtering

  • Fixed expressiveness: 5-tuple matching cannot encode stateful behavior, temporal patterns, or cross-flow correlation
  • Rule explosion: N threats × M protocols × K variants = combinatorial blowup of static rules
  • Reactive only: rules are written after an attack is understood; zero-day threats pass through
  • No adaptation: a fixed-threshold rate limit fails when traffic patterns shift
Key Insight: The gap is not in matching speed (eBPF is fast enough) but in expressiveness — what logic can the filter encode at all?

Current PacketScope Guarder

  • 32 static rules in BPF_MAP_TYPE_ARRAY
  • Sequential linear scan per packet
  • AI generates JSON rule descriptors only
  • Cannot express: rate limits, bloom filters, protocol parsing, state machines

Our Approach: Agent-Programmable eBPF

Instead of constraining the AI agent to emit {"src_ip": "...", "action": "drop"} rule descriptors, we let it generate arbitrary eBPF C code that compiles to kernel-verified XDP bytecode — turning the data plane itself into an AI-programmable defense surface.

Beyond Static Rules: New Capabilities

1. Adaptive SYN Flood Detection

Per-IP SYN rate tracking using hashed timestamp buckets. Dynamically drops IPs exceeding threshold — impossible with a static rule that has no concept of rate over time.

Stateful Per-IP Temporal

2. DNS Tunneling Detection

Tracks DNS query frequency per source IP using bloom filters. IPs with anomalously high DNS-over-UDP rates are flagged — static rules cannot count across packets.

Cross-Packet Bloom Filter Protocol-Aware

3. Coordinated Port Scan Detection

Detects distributed scans by tracking distinct destination ports per source IP. Triggers when an IP touches >N ports within a time window — requires state machines, not rules.

Distributed Counter Array Window-Based

4. TLS ClientHello Fingerprinting

Identifies malicious clients by matching TLS handshake byte patterns (JA3-like). Static rules operate at L3/L4 only; this filter operates at L7.

L7 DPI Fingerprint

5. Adaptive Rate Limiting

Implements token-bucket rate limiting with dynamic thresholds that adjust based on observed traffic baseline. Graceful degradation, not binary drop.

Token Bucket Self-Tuning

6. ICMP Covert Channel Blocker

Detects ICMP payloads with anomalous entropy (data exfiltration). Tracks per-flow ICMP byte ratios and blocks high-entropy ICMP streams.

Entropy Exfil Detection

Example: Agent-Generated SYN Flood Filter

User Intent (Natural Language)

"Detect and drop SYN flood attacks. If a source IP sends more than 50 SYN packets within a ~1 second window, drop all subsequent SYN packets from that IP."

Agent-Generated eBPF Logic

// Only inspect TCP SYN packets
if (pkt->protocol != PKT_PROTO_TCP)
    goto chain_next;
if (!(pkt->tcp_flags & PKT_TCP_SYN))
    goto chain_next;

// Hash source IP to a timestamp bucket
__u32 bucket = ip_hash5(pkt->src_ip);
__u64 now = pkt->timestamp;
__u64 window = 1000000000ULL; // 1 second in ns

// Check if this IP was seen recently
if (now - state->timestamps[bucket] < window) {
    state->counters[bucket & 0xF]++;
    if (state->counters[bucket & 0xF] > 50) {
        state->drop_count++;
        return XDP_DROP;
    }
} else {
    // New window: reset counter
    state->timestamps[bucket] = now;
    state->counters[bucket & 0xF] = 1;
}
state->match_count++;

What Makes This Impossible with Static Rules

  • Temporal state: tracks per-IP packet timestamps across a sliding window
  • Counting: maintains per-IP counters that reset every window
  • Threshold logic: "more than 50 within 1 second" requires arithmetic
  • Selective dropping: only drops after threshold; first N packets pass

Conclusion & Future Work

Contributions

  • First system enabling LLM agents to synthesize and hot-deploy eBPF XDP defense programs from natural language
  • 4-layer safety model ensuring that AI-generated code cannot compromise kernel integrity
  • Composable filter chain via BPF tail calls with zero-downtime deployment
  • Qualitative expressiveness leap from 5-tuple matching to stateful, temporal, cross-flow network defense
Key takeaway: By leveraging the eBPF verifier as an unforgeable safety oracle, we can safely hand the data plane to an AI agent — unlocking defense capabilities that no hand-written rule set could achieve.

Future Directions

  • Closed-loop feedback: Agent reads drop/pass counters from its deployed filter to iteratively refine thresholds
  • Multi-agent defense: Separate agents for DDoS, exfiltration, and reconnaissance, each occupying a tail call slot
  • Formal verification: Use SMT solvers to prove properties of agent-generated code beyond what the kernel verifier checks
  • TC/socket layer: Extend beyond XDP to TC and socket-level eBPF for egress filtering and process-level isolation
  • Federated filter sharing: Organizations share verified eBPF defense programs via signed artifact registry
